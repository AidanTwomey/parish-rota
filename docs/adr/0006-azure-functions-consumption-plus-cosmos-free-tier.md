# Azure Functions (Consumption) + Cosmos DB free tier

Compute is Azure Functions on a serverless, scale-to-zero plan: an HTTPS webhook for inbound WhatsApp, timer triggers for prompts, generation, reminders, and cover-request deadlines. The free monthly grant exceeds this workload by orders of magnitude. Storage is Cosmos DB's free tier (1000 RU/s, 25 GB), partition key `parishId`, chosen over Table Storage because it is equally £0 at this scale and its portal Data Explorer doubles as the admin escape hatch (ADR 0003). Infrastructure is declared in code so adding a parish is configuration (Bicep was the original choice; superseded by Terraform in ADR-0007). Residual running costs are WhatsApp template messages (~£2–3/month) and LLM intent-parsing calls.

## Amendment: Flex Consumption, not Consumption (Y1)

The plan is **Flex Consumption (FC1)**, not the classic Consumption plan (Y1) this ADR originally named. The first `terraform apply` failed creating the Y1 plan with `ExtendedCode 70007` — "Current Limit (Total VMs): 0". Y1 draws on a per-subscription, per-region **Dynamic VMs** quota which is zero on this subscription, is not exposed in the portal Quotas blade, and so cannot be raised without a support ticket. Every quota that *is* listed for UK South (EP/WS/Pmv3/Pv4) belongs to a paid always-on tier and would cost tens of pounds a month, which defeats the point of this ADR.

Flex Consumption has a separate quota pool — 250 cores per region by default, untouched by other plan types — so it sidesteps the problem rather than negotiating with it. It keeps the properties this ADR actually depends on: scale to zero, execution-time-only billing, a monthly free grant. It is also Microsoft's recommended serverless plan now, and is explicitly documented as supporting .NET 10 isolated, which Y1 was not.

Costs of the switch: Linux only (already true), no deployment slots (unused), one app per plan (unused), and a shorter list of supported regions — UK South must be checked with `az functionapp list-flexconsumption-locations` before assuming it is available. `FUNCTIONS_WORKER_RUNTIME` and `WEBSITE_RUN_FROM_PACKAGE` are deprecated on Flex; the runtime is a first-class resource argument and the deployment package lives in a blob container.
